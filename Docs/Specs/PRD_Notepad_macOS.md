# macOS 版 Notepad（Win11 复刻版）产品需求书

---

## 1. 项目概述

### 1.1 产品名称
**Notepad for macOS**（内部代号：NotePad-Mac）

### 1.2 产品定位
一款面向 macOS 用户的轻量级纯文本编辑器，**1:1 复刻 Windows 11 原生 Notepad 的全部功能与交互体验**，同时无缝融入 macOS 原生生态。目标用户为从 Windows 迁移至 macOS 的用户，以及习惯 Windows Notepad 极简操作逻辑的用户群体。

### 1.3 核心价值主张
- **零学习成本**：Windows 用户切换至 Mac 后，可立即获得完全一致的 Notepad 使用体验
- **极致轻量**：启动速度 < 500ms，内存占用 < 50MB
- **原生融合**：在保持 Windows 交互逻辑的同时，完美适配 macOS 菜单栏、快捷键、窗口管理及系统主题

---

## 2. 目标用户画像

| 用户类型         | 特征                                    | 核心诉求                                   |
| ---------------- | --------------------------------------- | ------------------------------------------ |
| Windows 迁移用户 | 刚购买 Mac，对 macOS 文本编辑工具不熟悉 | 找到与 Win11 Notepad 完全一致的替代品      |
| 跨平台开发者     | 经常在 Windows 与 Mac 之间切换工作      | 保持一致的文本编辑体验，减少上下文切换成本 |
| 极简主义用户     | 不需要 IDE 或富文本编辑器的复杂功能     | 快速打开、编辑、保存纯文本文件             |
| 系统管理员/运维  | 频繁查看和修改配置文件                  | 支持多种编码、大文件快速打开、状态栏信息   |

## 3. 功能需求（Functional Requirements）

### 3.1 核心编辑功能

#### FR-001 纯文本编辑
- 支持无格式纯文本的创建、编辑、保存
- 默认文件格式：`.txt`
- 支持打开任意扩展名的纯文本文件（如 `.ini`, `.log`, `.json`, `.xml`, `.md` 等）
- 最大支持打开 **10MB** 以内的文本文件（超过时提示并支持只读模式）

#### FR-002 多标签页（Tabs）
- 支持多标签页同时打开多个文件
- 标签页显示文件名，未保存文件在名称前显示圆点 `●`
- 支持标签页拖拽排序
- 支持标签页拖拽出窗口形成新窗口
- 右键标签页菜单：关闭 / 关闭其他 / 关闭右侧 / 复制标签 / 在 Finder 中显示
- 快捷键：`⌘N` 新建标签，`⇧⌘N` 新建窗口，`⌘W` 关闭标签，`⇧⌘]` / `⇧⌘[` 切换标签

#### FR-003 自动保存与状态保持
- 开启自动保存后，编辑内容实时自动保存（无需手动按 `⌘S`）
- 关闭应用或标签页时无需弹窗确认（已自动保存）
- 重新打开应用时，自动恢复上次会话的所有标签页及光标位置
- 自动保存可开关（默认：开启）

#### FR-004 查找与替换
- **查找**（`⌘F`）：
  - 支持普通文本匹配
  - 支持区分大小写选项
  - 支持向上/向下搜索
  - 高亮所有匹配项，当前匹配项用不同颜色高亮
  - 查找框悬浮于编辑区顶部，不遮挡内容
- **替换**（`⌥⌘F`）：
  - 支持单个替换与全部替换
  - 替换框展开于查找框下方
- 支持正则表达式（扩展功能，Win11 原版无，作为增值功能）

#### FR-005 撤销与重做
- 无限级撤销（`⌘Z`）与重做（`⇧⌘Z`）
- 编辑操作历史在标签页切换后仍保持独立

#### FR-006 剪切、复制、粘贴
- 完全支持系统剪贴板
- 支持纯文本粘贴（去除格式）
- 粘贴时保持原始文本编码

---

### 3.2 文件操作功能

#### FR-007 新建文件
- `⌘N`：新建标签页
- `⇧⌘N`：新建窗口
- 新建文件默认无标题，首次保存时提示命名

#### FR-008 打开文件
- `⌘O`：打开文件对话框（调用 macOS 原生 NSOpenPanel）
- 支持拖拽文件到 Dock 图标、窗口或标签栏打开
- 支持从 Finder 右键"使用 Notepad 打开"
- 支持打开最近文件（菜单：文件 → 打开最近使用的，保留 15 条记录）

#### FR-009 保存文件
- `⌘S`：保存当前文件
- `⇧⌘S`：另存为
- 保存时自动检测编码，保持原文件编码不变
- 首次保存时弹出 NSSavePanel，默认文件名 `*.txt`

#### FR-010 编码支持
- 支持以下编码格式（与 Win11 Notepad 保持一致）：
  - UTF-8（默认，带 BOM / 不带 BOM）
  - UTF-16 LE / UTF-16 BE
  - UTF-32 LE / UTF-32 BE
  - ANSI / Windows-1252
  - 中文编码：GB2312 / GBK / GB18030 / Big5
- 状态栏实时显示当前文件编码
- 打开文件时自动检测编码（优先级：UTF-8 > UTF-16 > GBK > ANSI）
- 编码检测失败时，允许用户手动选择编码重新打开
- 保存时可手动切换编码格式

#### FR-011 换行符支持
- 支持三种换行符格式：
  - CRLF（`\r\n`，Windows 默认）
  - LF（`\n`，Unix/macOS 默认）
  - CR（`\r`，旧 Mac 系统）
- 状态栏显示当前换行符格式
- 保存时可选择换行符格式（默认保持原格式，新建文件默认 LF）

---

### 3.3 界面与显示功能

#### FR-012 界面布局（1:1 复刻 Win11 Notepad）
- **标题栏**：显示当前文件名 + " - Notepad"
- **菜单栏**：完全复刻 Win11 Notepad 的菜单结构（见 4.1 节）
- **编辑区**：纯白/纯黑背景（根据主题），等宽字体，无行号（保持原版）
- **状态栏**：底部显示以下信息（从左到右）：
  - 行号, 列号（如 `Ln 12, Col 34`）
  - 缩放比例（如 `100%`）
  - 换行符格式（如 `Windows (CRLF)` / `Unix (LF)`）
  - 编码格式（如 `UTF-8`）
- 状态栏可开关（视图 → 状态栏）

#### FR-013 主题与外观
- **浅色模式**：纯白背景 `#FFFFFF`，黑色文字 `#000000`
- **深色模式**：纯黑背景 `#1E1E1E`，白色文字 `#CCCCCC`
- 自动跟随 macOS 系统主题设置（`NSApp.appearance`）
- 支持手动切换：视图 → 主题 → 浅色 / 深色 / 跟随系统

#### FR-014 字体设置
- 菜单：格式 → 字体
- 调用 macOS 原生字体面板（`NSFontPanel`）
- 默认字体：`SF Mono`（等宽字体），字号 12pt
- 字体设置全局生效（所有标签页共享）
- 支持字体平滑渲染（`NSAntialiasText`）

#### FR-015 缩放功能
- 视图 → 缩放 → 放大（`⌘+`）/ 缩小（`⌘-`）/ 恢复默认（`⌘0`）
- 缩放范围：10% - 500%，步进 10%
- 状态栏实时显示当前缩放比例
- 支持触控板双指捏合缩放

#### FR-016 自动换行
- 格式 → 自动换行（`⌥⌘W`）
- 开启后，文本在窗口边缘自动折行
- 关闭后，出现水平滚动条
- 默认：开启

#### FR-017 始终在最前
- 视图 → 始终在最前
- 开启后，Notepad 窗口悬浮于所有其他应用窗口之上
- 默认：关闭

---

### 3.4 打印功能

#### FR-018 页面设置
- 文件 → 页面设置
- 调用 macOS 原生页面设置面板
- 支持设置纸张大小、方向（纵向/横向）、页边距

#### FR-019 打印
- `⌘P`：打印当前文档
- 调用 macOS 原生打印面板（`NSPrintPanel`）
- 支持打印预览
- 支持选择打印机、份数、页面范围

---

### 3.5 系统集成功能

#### FR-020 macOS 原生菜单栏
- 应用完全融入 macOS 菜单栏（而非 Win11 的 Ribbon 或汉堡菜单）
- 菜单结构见第 4 节

#### FR-021 系统服务
- 支持 macOS "服务" 菜单集成
- 支持选中文字后通过服务菜单进行系统级操作

#### FR-022 文件关联
- 安装时自动关联 `.txt` 文件
- 支持在 Finder 中右键 `.txt` 文件 → 打开方式 → Notepad
- 支持将 `.txt` 默认打开方式设为 Notepad

#### FR-023 触控栏（Touch Bar）支持
- 默认显示：新建、打开、保存、查找、自动换行开关
- 编辑文本时显示：剪切、复制、粘贴、撤销、重做

#### FR-024 快捷指令（Shortcuts）支持
- 支持 macOS Shortcuts App 调用
- 提供快捷指令动作：用 Notepad 打开文件、创建新文本文件

## 5. 非功能需求（Non-Functional Requirements）

### 5.1 性能需求

| 指标                     | 要求                                       |
| ------------------------ | ------------------------------------------ |
| 冷启动时间               | < 500ms（M1/M2 Mac），< 800ms（Intel Mac） |
| 热启动时间               | < 200ms                                    |
| 打开 1MB 文件            | < 1s                                       |
| 打开 10MB 文件           | < 3s                                       |
| 内存占用（空文档）       | < 50MB                                     |
| 内存占用（10 个标签页）  | < 150MB                                    |
| 编辑 10MB 文件时打字延迟 | < 16ms（60fps 流畅）                       |

### 5.2 兼容性需求

- **最低系统版本**：macOS 12 Monterey（支持 Apple Silicon + Intel）
- **推荐系统版本**：macOS 13 Ventura 及以上
- **架构支持**：Universal Binary（同时支持 Intel x86_64 和 Apple Silicon arm64）
- **Retina 显示**：完美支持 Retina / HiDPI 显示
- **多显示器**：支持在不同 DPI 显示器之间拖拽窗口

### 5.3 可靠性需求

- 崩溃率 < 0.1%
- 自动保存机制确保崩溃时不丢失超过 1 秒的编辑内容
- 支持从临时备份恢复未保存的文件

### 5.4 可访问性需求（Accessibility）

- 完全支持 macOS VoiceOver 屏幕阅读器
- 支持全键盘导航（无需鼠标即可完成所有操作）
- 支持动态字体（Dynamic Type）
- 符合 WCAG 2.1 AA 级对比度标准

### 5.5 国际化需求

- 第一阶段：简体中文、繁体中文、英文
- 第二阶段：日文、韩文、德文、法文、西班牙文、俄文
- 界面语言跟随系统设置
- 编码自动检测优先支持多语言环境

## 6. 技术架构建议

### 6.1 推荐技术栈

| 层级     | 技术方案                                   | 说明                           |
| -------- | ------------------------------------------ | ------------------------------ |
| 开发语言 | Swift / SwiftUI + AppKit                   | 原生 macOS 开发，性能最优      |
| 文本引擎 | NSTextView + NSLayoutManager               | macOS 原生文本渲染，支持大文件 |
| 编码检测 | ICU (International Components for Unicode) | 业界标准编码检测库             |
| 自动保存 | NSDocument + NSFileCoordinator             | 利用 macOS 原生文档架构        |
| 偏好设置 | UserDefaults + CFPreferences               | 系统级配置存储                 |
| 更新机制 | Sparkle 框架                               | macOS 标准自动更新方案         |

### 6.2 备选技术栈

| 层级       | 技术方案                 | 适用场景                    |
| ---------- | ------------------------ | --------------------------- |
| 跨平台方案 | Electron + Monaco Editor | 需要同时开发 Windows 版本时 |
| 跨平台方案 | Tauri + Rust             | 追求更小体积的跨平台方案    |

> **建议**：优先采用 **Swift + AppKit** 原生开发，以确保最佳的性能、最小的包体积（< 5MB）和最原生的 macOS 体验。

## 9. 验收标准（Acceptance Criteria）

### 9.1 功能验收

- [ ] 从 Windows 11 复制一份 `.txt` 文件到 Mac，用本应用打开，内容、编码、换行符完全一致
- [ ] 在 Mac 上编辑保存后，复制回 Windows 11 Notepad 打开，显示完全一致
- [ ] 所有 Win11 Notepad 支持的编码格式均可正确打开和保存
- [ ] 快捷键映射表中的所有功能均可正常使用
- [ ] 崩溃后重新打开应用，未保存内容可恢复

### 9.2 体验验收

- [ ] Windows 用户无需阅读文档即可上手使用
- [ ] 菜单栏结构与 Win11 Notepad 逻辑一致，同时符合 macOS 规范
- [ ] 深色模式切换无闪烁，颜色与 Win11 深色 Notepad 一致
- [ ] 状态栏信息实时更新，延迟 < 100ms

## 10. 风险与应对

| 风险                                | 影响 | 应对措施                                         |
| ----------------------------------- | ---- | ------------------------------------------------ |
| macOS 原生文本引擎与 Win11 渲染差异 | 高   | 精确调校 NSTextView 的字体渲染参数，确保视觉一致 |
| 编码自动检测准确率不足              | 高   | 引入 ICU 库，提供手动编码选择兜底方案            |
| 大文件（> 10MB）编辑卡顿            | 中   | 采用虚拟化/分页加载策略，限制单次渲染行数        |
| App Store 审核对"复刻"产品的质疑    | 中   | 强调"兼容体验"而非"品牌侵权"，UI 适当差异化      |
| 用户期望与 macOS 原生体验冲突       | 低   | 提供"原生模式"开关，允许切换为 macOS 标准行为    |
